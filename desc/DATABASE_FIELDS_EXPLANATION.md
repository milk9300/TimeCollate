# 数据库字段说明文档

本文档旨在说明 `books`（书籍表）和 `photos`（图片表）中部分核心字段的作用及其在目前版本中可能为空的原因。

## 1. 书籍表 (books)

| 字段名 | 作用描述 | 为空/Null 的原因 |
| :--- | :--- | :--- |
| `cover_oss_key` | **OSS 存储键**。记录封面图在阿里云 OSS 中的具体路径。系统利用它生成带有效期的**签名 URL**（提高安全性）和**缩略图**（进行性能优化）。 | 1. **历史遗留数据**：在完善 OSS 集成前的老数据只存了静态 URL。<br>2. **外部链接**：如果封面使用的是网络图片 URL，则没有对应的 OSS 键。 |
| `author` | **作者名称**。书籍展示时显示的署名。 | 用户在创建书籍时未填写（可选字段）。 |
| `preface` | **引言/序言**。书籍开头的一段文字描述。 | 用户尚未编写序言（可选字段）。 |
| `deleted_at` | **软删除标记**。如果非空，表示书籍已移入回收站，30天后会自动永久删除。 | 只有被用户手动删除并进入回收站的书籍才会填充此字段。 |

## 2. 图片表 (photos)

| 字段名 | 作用描述 | 为空/Null 的原因 |
| :--- | :--- | :--- |
| `caption` | **图片描述/图注**。用户为单张照片添加的说明文字。 | **可选字段**。用户在编辑页面或库中尚未为该图片输入任何文字。 |
| `width` | **图片原始宽度**（像素）。预留给未来实现**智能瀑布流**或**拼贴排版算法**，以根据宽高比自动调整布局。 | **功能预留/待实现**。目前的后端上传逻辑（`upload.ts`）尚未集成图片处理库（如 Sharp）来提取元数据，前端也暂未在保存时提交这些信息。 |
| `height` | **图片原始高度**（像素）。作用同上。 | **同上**。目前属于数据库结构已就绪，但业务逻辑尚未对接填充的阶段。 |

## 总结建议
目前这些字段为空不会影响系统的核心运行。
- **关于 `cover_oss_key`**：对于新上传的封面，建议确保 key 被正确保存，以便利用 OSS 的图片压缩功能。
- **关于 `width/height`**：如果未来需要实现高级拼贴布局（类似杂志排版），建议在后端上传接口增加宽高自动识别逻辑。
