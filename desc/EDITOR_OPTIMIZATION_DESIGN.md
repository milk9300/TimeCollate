# TimeCollate (拾光集) 编辑器体验深度重构与优化方案

作为一款以“高品质物理相册定制”为核心的产品，**编辑器的编辑体验**是决定产品成败的关键。目前系统的“左侧表单录入 + 右侧 passive 预览”模式在开发初期能够跑通业务，但对于追求“印刷级排版”和“流畅设计感”的生产级应用，仍存在较大的优化空间。

本方案针对编辑器的核心缺陷，提出四个维度的重构与优化设计：

---

## 1. 核心优化维度

### 1.1 所见即所得（WYSIWYG）双向交互重构

#### 【痛点】
目前用户修改文字或调整图片，必须在左侧表单或素材池中进行，右侧画布仅用于被动回显。这打破了用户的视觉直觉，增加了认知负担。

#### 【改造方案：Canvas 交互层激活】
通过将右侧预览 Canvas 从“被动渲染”升级为“主动交互”，支持以下操作：

1.  **文本双击内联编辑 (Inline Editing)**：
    在 `BookRenderer` 及其子布局（如 `MagazineLayout`）中，将普通的文本展示标签升级为具有 `contentEditable` 属性的编辑容器。
    *   **架构设计**：为了不破坏 `react-zoom-pan-pinch` 的拖拽体验，在双击文本时临时禁用画布的缩放/平移手柄，激活 `contentEditable`；编辑完成（Blur 或 Enter）后，触发防抖（Debounce）并将最新内容同步回 Zustand Store，最后重新启用画布手柄。
2.  **图片槽直观交互 (Slot Interactions)**：
    *   **点击唤起快捷工具条**：点击布局中的任意图片，原地弹出一个浮动工具条，提供“替换”、“删除”、“添加图注（Caption）”和“平移裁剪（Pan/Zoom）”功能。
    *   **直接拖拽替换**：支持从左侧素材库（或直接从电脑桌面）将图片拖拽至预览区域对应的图片槽内，自动触发上传和绑定。

---

### 1.2 非破坏性图片裁剪与平移（Pan & Zoom）

#### 【痛点】
目前布局中的图片通过 CSS 的 `object-cover` 进行盲填。如果用户上传的照片人物偏向边缘，可能会出现“裁头/切脸”的严重排版事故，且用户无法调整。

#### 【改造方案】
引入前端非破坏性的图片视口调整（类似于 CSS `object-position` 和 `scale` 的可视化修改）：

```typescript
// 扩展 Photo 领域模型定义
export interface PhotoAdjustment {
    scale: number;      // 缩放比例 (e.g. 1.2)
    xOffset: number;    // X 轴偏移百分比 (0-100)
    yOffset: number;    // Y 轴偏移百分比 (0-100)
}
```

*   **交互实现**：当用户点击图片槽的“微调”按钮时，该图片槽进入“焦距编辑模式”。用户可以直接在预览图上拖拽平移图片，或通过滑块（Slider）放大缩小。
*   **渲染实现**：前端通过控制 `style={{ objectPosition: `${xOffset}% ${yOffset}%`, transform: `scale(${scale})` }}` 实时呈现。
*   **PDF/打印导出兼容**：无头浏览器 Playwright 会完整保留对应的 CSS style 属性，从而保证生成的 PDF 与用户在屏幕上看到的位置分毫不差。

---

### 1.3 双页对开布局（Two-Page Spread View）

#### 【痛点】
物理书在阅读时是双页对开的。目前单页（Single Page）的设计割裂了排版的整体感。设计师和用户无法观察到“左页配图 + 右页文字”这种经典的对开视觉平衡。

#### 【改造方案】
将预览区域从“单页视口”重构为“对开本（Book Spread）模式”：

*   **页面组合策略**：
    *   第一页：封面（单独单页，靠右）。
    *   第二页、第三页：第一对开（对开双页，左右拼接，中间有模拟书缝阴影）。
    *   最后一页：封底（单独单页，靠左）。
*   **状态模型调整**：
    *   前端状态树以 `Spread`（跨页对）为单位调度，支持用户“整组跨页拖拽”或“左右页对调”。

---

### 1.4 编辑器历史记录回滚（Undo/Redo Engine）

#### 【痛点】
相册排版是一个反复调优的过程，用户经常会产生“删错页面”、“换错布局”或“误删照片”等误操作，没有撤销功能会导致极差的用户体验。

#### 【方案一：Zustand 中间件模式 (推荐)】
引入 Zustand 的历史管理器（或自定义 History 切片），拦截 Store 的 Mutator 操作：

```typescript
// 简单的 Undo/Redo 历史栈状态定义
interface HistoryState {
    past: Book[];
    future: Book[];
}
```

*   **机制**：每次调用 `saveBook` 前，将当前的 `currentBook` 深拷贝并推入 `past` 栈中；当触发 `Undo` 时，将当前状态推入 `future` 栈，并从 `past` 栈顶取出状态覆盖 `currentBook`。同时对网络同步进行**节流（Throttle）**，避免频繁的 API 请求。

---

## 2. 候选重构架构与开发排期

为了保证核心编辑器的平稳过渡，我们拟定两条重构路线供决策：

### 路线 A：渐进式表单融合（低开发风险，1.5 周）
*   **策略**：保留目前的左右布局，但在右侧画布的图片槽上增加快捷操作悬浮按钮，提供“图注编辑”与“物理平移（CSS object-position 调整）”；点击文字块自动定位到左侧输入框并高亮。
*   **适用场景**：希望快速上线稳定版本，优先保障核心功能跑通。

### 路线 B：完全体 Canvas WYSIWYG（极致体验，3 周）
*   **策略**：隐藏左侧表单面板（仅保留素材桶）。所有的文本修改、版式微调、图片定位、文字溢出警告，全部在右侧 Canvas 上直观完成。
*   **适用场景**：打造高端精品化定位，对标业内一线相册编辑软件的排版体验。
